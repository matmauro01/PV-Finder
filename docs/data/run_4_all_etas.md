### 1. Track selection is now uniform — the old sample was contaminated

The old files carried **65.8 tracks/event confined to exactly
2.0 <= |eta| <= 2.5** with `pT` down to 0.5 GeV (0.9 GeV everywhere else), plus
`|d0|` out to 49 mm and `sigma(d0)` to 4.4 mm — including 16 tracks/event with
`|d0| > 1 mm` inside `|eta| < 2`.

The new files apply one selection everywhere: **`pT >= 0.9 GeV`,
`|d0| <= 1 mm`, `sigma(d0) <= 0.35 mm`, `|z0| <= 200 mm`**. The remote README
attributes it to the ITk paper ([arXiv:2412.15090]) table 5, applied at CKF reco
level, giving table-6 content.

So the new sample is both wider in eta *and* cleaner.

### 2. HGTD timing is now real

Acceptance is 0 below `|eta| ~ 2.25`, then **70–79 % flat over
2.5 < |eta| < 3.9**. The `34.7 ps` single-hit population is largely replaced by
20–25 ps. The "timing is not usable for the finder" negative result in the
technical note was reached at 3.9 % coverage confined to the 2.4–2.5 sliver and
no longer describes the data.

### 3. Forward tracks buy reach, not precision

Fisher bound `sigma_vtx = 1/sqrt(sum_tracks 1/sigma_z0^2)` per truth vertex,
central-only vs all tracks on the *same* vertices: the gain is **0.1–0.2 % at
every multiplicity**. `sigma(z0)` runs from 65 um at `eta = 0` to ~2.8 mm at
`|eta| = 3.7`, so a forward track carries ~1/2000 the weight of a central one.

What they add is reach: **19.2 truth vertices/event (17.3 % of the nTracks >= 2
denominator) have fewer than 2 central tracks** and only clear the threshold
because of the forward tracks. Their median achievable sigma is 257 um (vs 36 um
for regular vertices), and only 46 % are localisable to better than PVF's own
223 um vertex-vertex resolution.

## Consequences for training and evaluation

1. **Efficiency is not comparable to the published `|eta| < 2.5` numbers.** The
   denominator grows 17.6 % with the hardest vertices in the sample, so absolute
   efficiency falls for PVF *and* AMVF. Quote both denominators (nTracks >= 2
   over all tracks, and over `|eta| < 2.5` tracks only).
2. **AMVF gains no vertices** (101.17 -> 101.27) despite +52 % tracks per vertex:
   it attaches forward tracks to vertices it already had. Any vertex PVF recovers
   from the forward-only population is a gain AMVF structurally cannot match.
3. **Refit the resolution model before converting.** At fixed truth nTracks the
   achievable resolution is now *worse* (x1.18 at nTrk 20–50, up to x1.74 at
   2–3), because nTracks counts low-information forward tracks. Neither `hllhc`
   nor `hllhc_corrected` applies; the refit moves `sigma` *up* at fixed n.
   Sequence: `diagnostics/amvf_resolution_vs_ntracks.py` ->
   `diagnostics/resolution_fit_v2.py` (the background-corrected fitter) ->
   register a preset in `data/resolution_presets.py`.
   Consider that `sigma(n)` is now a poor parameterisation at all, since n mixes
   65 um and 2.8 mm tracks.
4. **Use `--max-tracks-per-sub 1536`.** A full z0 scan over 6.43 M sub-events
   gives a max of **1066**, already above the 1024 default, and that is only
   ~12 % of the pool. Truncation is z0-ordered: it drops the highest-z0 tracks
   while the target histogram keeps their PVs. `--max-pv 300` is safe (max truth
   PV/event = 208 over 4.42 M events).

## Fetching more of it

Use `scripts/fetch_run4_all_etas.sh`, which is idempotent and resumable.

**Never use `sftp get -r` on this directory.** sftp overwrites rather than
skips, so re-running a recursive get destroys files that were already complete
(this happened on 2026-07-31; see JOURNAL). The script uses
`rsync --size-only --inplace --partial` with retries, then verifies every ROOT
by opening it with uproot.

Authentication is the one manual step: run `ssh lxplus true` once (password +
2FA) to open the ControlMaster socket declared in `~/.ssh/config`; the script
reuses it and errors out with instructions if none exists.
